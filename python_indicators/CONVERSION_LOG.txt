A. CONVENTIONS
--------------
* Faithful, line-by-line ports. MQL class, method and function names and
  argument orders are kept, so an indicator port reads like its .mq5.
* MQL5 semantics come from mql5_include/mql_runtime.py:
    - EMPTY_VALUE = DBL_MAX (1.797e308); converted to NaN only when a plugin
      returns its plot arrays (NaN = "draw nothing" in this app);
    - idiv/imod = C integer division (truncates toward zero);
    - fdiv = IEEE float division (x/0 = inf, 0/0 = nan instead of an exception);
    - 32-bit wrap-around (as_int32) where the source relies on int overflow.
* Series indexing (ArraySetAsSeries true): kept wherever the source uses
  it (index 0 = newest bar). Plugins return forward arrays (index 0 = oldest).
* Source bugs that change the numbers are REPRODUCED, not fixed, and are
  documented in the module docstring ("Faithfully reproduced ..."). The goal
  is identical output to MetaTrader.
* Terminal data functions (CopyRates, iClose(symbol, tf, shift), SymbolInfo*,
  MarketInfo, ...) read from mql5_include/terminal.py: a stand-in terminal
  that holds bar DataFrames per (symbol, timeframe) plus a contract spec.
* Chart-object, canvas and GUI code has no counterpart: this app draws an
  indicator from the arrays it returns, not from chart objects. Pure-drawing
  includes are therefore not ported, and object calls inside ported code are
  no-ops.

Status legend
  PORTED      full port; the module docstring lists any quirks
  PARTIAL     the computing part is ported; terminal/account/UI parts are not
  SAME AS     identical or near-identical copy of another file; one module
              covers both
  NOT PORTED  no computing content for a backtester indicator (reason given)
  INDICATOR   an .mq5 that sits in the Include folder; converted as a plugin
